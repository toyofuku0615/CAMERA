# 黒い服と白いシールのライブ実演

ホームの「チェックを開始」は高速ライブ専用です。撮影後の結果画面を待たずに動画へ枠を描画します。従来の自動撮影は「4方向を撮影して確認」から利用できます。

## 当日の準備

1. このブランチのコードをNetlify/Vercelなどへビルドし、発行されたHTTPS URLをiPhone Safariで開く。公開方法はREADME参照。この改修作業では手動デプロイは行っていません。GitHub連携によるプレビューがある場合は、そのHTTPS URLで確認できます。
2. 明るい室内、白やグレーのシンプルな背景を選ぶ。窓を背にせず、服を均一に照らす。
3. 無地の黒い服の背中に、約3cm四方の白いシールを貼る。白いロゴ、ネックレス、強い光沢を避ける。
4. iPhoneを胸の高さに固定。「チェックを開始」でカメラを許可。
5. 黒い服がガイドの中で十分大きく写る位置へ移動。まず約1mを目安にし、端末の画角に合わせて調整する。遠すぎると縮小画像でシールが小さくなる。
6. 音声案内を確認し、ゆっくり背中を向けて一瞬静止する。音声が再生されなくても映像の枠で継続できる。

## 実演

- 枠はそのフレームから計算した白い候補。初回は破線、連続して確認できたら実線になる。
- 「白いシールの候補があります」と短く案内する。音声の繰り返しは間隔を空ける。
- 「画面を止めて確認」で、その解析映像と枠を固定する。PAUSED表示中はライブではなく、カメラも停止している。
- シールを外し「ライブ映像に戻る」。新しい動画で候補が消えることを確認する。
- シールの位置を変え、枠が実際の場所へ移ることを確認する。
- 「終了して映像を破棄」でカメラと一時画像を破棄する。アプリをバックグラウンドにした場合も停止し、復帰後は再開操作を行う。

モデルのダウンロードや、4方向の撮影完了はライブ開始の条件ではありません。解析の目標は約10回/秒で、実機の速度はまだ未測定です。

## うまく見つからない場合

まず服とシールがガイド内に収まっているか確認する。シールが端にあると周囲の生地を十分確認できないため、立ち位置を調整する。小さく写る場合は近づく。暗い、逆光、光沢、ブレがある場合は照明を調整して静止する。

開発サーバーでは `/?debug=1` に処理時間・解析回数・候補と除外理由が出る。`src/config.ts` の `LIVE` で白の明度（145）、黒の上限（95）、局所明暗差（65）、最小面積（幅320pxで6画素）、黒い周辺領域の割合（0.78）を調整できる。`LIVE_GUIDE` が解析枠。闇雲に閾値を下げると、肌・反射・背景の誤検出が増える。

ライブはガイド内の黒い領域が服であることを前提にしている。暗い背景にある白い模様、服の白いロゴや反射を異物と区別できない場合がある。「候補を探しています」は異物なしの保証ではない。

## iPhoneでの確認記録

当日使うiPhone／Safariと会場で、シール1枚10回、2枚10回、なし10回を別々に試す。機種、iOS、照明、距離、シールの位置、最初に枠が出るまでの時間、位置追従・除去の反映、誤検出、音声、一時停止と再開を記録する。検出に失敗した回も分母に入れる。

本実装での実機試行は0回。合成カメラと実人物の参照写真へデジタルで貼ったパッチの結果から、iPhone精度9/10などを達成したとは判断していない。必要に応じ、失敗した元画像または短い動画と、同条件でシールを外したものを提供すると原因を調べられる。写真・動画をGitへコミットする必要はない。
