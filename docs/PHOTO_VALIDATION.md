# 実写真による検証

本改修の背景条件ごとの実物シール精度は未測定です。公開参照写真に白いパッチや背景を合成した試験を実機の10回撮影へ数えてはいけません。

## 必要な写真

iPhoneのSafariで撮影した、**無地の服を着た同じ人物の背面（最初は黒いセーター＋白いシール）**のJPEGまたはPNGを提供してください。顔は背面であれば写る必要はありません。肩〜腰と、服の輪郭が写るようにしてください。明るい均一な照明・約1.5〜2m・胸の高さの固定カメラ・約3cm四方の白いシールが基本条件です。

背景条件：白い壁、暗い壁、家具／本棚、複数色や模様、窓の自然光、オフィス／会議室。まずは白い壁・暗い壁・家具の3条件があれば原因調査を開始できます。

各背景で以下をそれぞれ独立に10回撮影してください。

- 白シール1枚：背面の肩付近・中央・下部へ位置を変える。目標9/10。
- 白シール2枚：背面の離れた場所に貼る。両方正しく検出し、余計な候補がない回を成功とする。目標8/10。
- シールなし：同じ服・照明・距離。誤検出なし目標8/10。

計6背景×3条件×10回＝180枚。最初の原因調査なら、失敗した元画像と、同条件でシールを取り除いた画像の2枚だけでも有用です。モデルで識別しにくい背面・側面の連続フレームもあるとフレーム間のずれを調べられます。撮影日、iPhone機種、iOS、向き、距離、照明、シールの実寸も記録してください。

人物写真をGitにコミットする必要はありません。本人の許可を得た写真だけを `private-fixtures/` に置いてください。このフォルダと検証出力は.gitignoreに含まれます。

最初の2枚に加え、可能なら明るい無地の服＋暗いシール、紺などの無地の服＋色付きのシールについても、付着あり／除去後の画像を用意してください。服の色ごとの目標は独立して評価し、黒い服の結果だけで他の色の精度を保証しません。

## 診断画面

`npm run dev` の `/dev` に画像を入力します。同じ向きの連続画像は最大8枚まで選択できます。元画像、人物マスク、服の解析マスクと範囲、候補、採用・除外理由、1フレームのみ／複数確認、モデル推論時間を確認してください。

## 記録を自動生成する

`private-fixtures/manifest.json` の例：座標は画像の表示方向に合わせた元画像の画素座標です。EXIFの向きをブラウザが適用した後の座標で指定してください。

```json
{
  "sourceLabel": "physical-iPhone: iPhone機種 / iOS / 撮影日",
  "photos": [
    {"file": "white-one-01.jpg", "background": "white-wall", "condition": "one", "expected": [{"x": 310, "y": 420, "width": 24, "height": 25}]},
    {"file": "dark-two-01.jpg", "background": "dark-wall", "condition": "two", "expected": [{"x": 280, "y": 390, "width": 24, "height": 25}, {"x": 360, "y": 500, "width": 24, "height": 25}]},
    {"file": "furniture-none-01.jpg", "background": "furniture", "condition": "none", "expected": []}
  ]
}
```

```sh
# 別のターミナルで起動したローカル開発サーバーが必要
npm run dev
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:photos
```

画像を外部へ送らないよう、評価コマンドはlocalhost／127.0.0.1の開発サーバーだけを許可します。JPEGとPNGの画像データはブラウザ内でデコードします。出力は `validation-results/physical-photos.json`。判定不能も失敗に数えます。検出枠と正解枠のIoUが0.2を超え、余分な候補がないことを成功条件にします。同じ写真の使い回しはハッシュで拒否します。条件ごとに10枚未満なら目標の評価は保留です。写真がなければコマンドは未実施を明示して終了します。
