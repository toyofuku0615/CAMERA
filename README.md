# BACKSTAGE

大切な予定の前に、自分では見えない服の乱れを確認する、iPhone Safari向けWebアプリ。React / TypeScript / Vite。黒い無地のセーター上の白いシール・テープに対象を絞ったMVPです。

**コード実装と合成画像による自動検証は実施。iPhone実機・実際のセーター写真での精度測定とHTTPS公開は未実施です。完成条件の実機検出精度を達成したとは判断していません。**

## 起動・ビルド

Node.js 24 LTS、npm 11（この環境で確認済み）。依存関係は package-lock.json で固定しています。APIキー・アカウント・バックエンドは不要です。

```sh
cd /workspace/CAMERA
npm ci
npm run dev
```

ViteのアドレスはPC開発用です。iPhoneのカメラはHTTPSが必要なので、LANのHTTPアドレスでは利用できません。localhostを公開URLとして使用しないでください。

```sh
npm run build
npm run preview
npm test
npx playwright install chromium
npm run test:e2e
```

システムのChromiumを使う場合（このクラウドで検証）：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

ブラウザをホーム以外に導入する場合は、インストール時と実行時に同じ `PLAYWRIGHT_BROWSERS_PATH` を設定してください。

## 実装した体験

- ホーム → 撮影準備 → 自動撮影 → 解析中 → 結果の5画面。
- フロントカメラ、`playsInline` / `muted`、目標720×960、最大30fps。実際の解像度は端末が選びます。
- 約3秒の準備 + 各方向6秒 = 約27秒。正面→側面①→背面→側面②。各方向最後の0.75秒で4枚取得。
- 音声の日本語案内、視覚カウントダウン。音声の再生可否で撮影を止めません。向きはユーザーが案内に従って変えます。
- 最も鮮明で解析可能なフレームを選び、複数フレームで一致した候補だけを表示。
- オレンジの検出枠、方向別表示、画像拡大、全体再撮影、判定不能方向のみの再撮影。
- カメラ拒否・未対応・切断・フレーム取得失敗・服の範囲不足・鮮明度不足を案内。「異物なし」と区別。
- バックグラウンド移行・終了・中止・解析開始でカメラを停止。終了・再チェックで以前の画像参照を破棄。
- セーフエリア、押しやすい操作、キーボード操作、動きを減らすOS設定に対応。

## 画像解析の構造と限界

MediaPipeを使用せず、指定された撮影環境に限定した**ガイドに基づく人物・服の推定**を使用しています。肩・腰のランドマークや人物セグメンテーションは実装していません。

1. 撮影画像を長辺最大960pxで保持し、解析画像を幅最大480pxへ縮小。
2. ガイド内の最大の連結した暗い領域を黒い生地として推定。縦幅・横幅・面積を検査。
3. 明るい画素の連結成分を抽出。面積・形状・周囲の暗い生地の割合・明暗差を検査。シール自体は生地マスクから除外せず、その周辺が生地かを確認。
4. 白い壁につながる領域、ガイド端に接する候補、四辺が生地で囲まれていない候補を除外。
5. ラプラシアンの平均二乗値で鮮明度を評価。各方向で最低2枚が解析可能であること、候補が複数フレームで一致することを確認。
6. ボックスを撮影画像の元座標へ変換しSVGで表示。

プレビューはCSSで反転、撮影画像はCanvasで一度反転して保存します。解析・結果画像・枠は同じ反転済み座標です。左右の部位は身体側として断定せず「画像左上部」などと表示します。

対象は明るい単純背景・黒い無地の服・中央に収まる上半身です。濃い背景、柄、襟や袖口、服の端のシール、細いテープ、強い反射、非常に小さいシール、横向きで細くなった服では見落としや誤検出があり得ます。黒い物体を服と誤認する可能性もあり、人体であることや全範囲の確認は保証しません。候補をあらかじめ固定する処理はありません。

## 開発用検証

`npm run dev` の `/dev` にアクセスします。本番ビルドの通常UIには存在しません。

静止画像をアップロードし、明度・明暗差・面積・暗い生地・周囲の生地割合・余白・鮮明度を調整できます。変更は即時解析され、青のガイド範囲・緑の生地外接範囲・オレンジの検出枠を表示します。実際の生地輪郭を緑で表示する機能ではありません。画像は送信せず、変更値は画面内だけに保持します。JPEG / PNG推奨。ガイド位置に合わせた写真を入力してください。

## 設定と主要ファイル

| ファイル | 役割 |
| --- | --- |
| `src/config.ts` | アプリ名、撮影時間、枚数、撮影ガイド、検出パラメータの一元管理 |
| `src/services/camera.ts` | カメラ許可・停止・反転したフレーム取得 |
| `src/services/capture.ts` | 中止可能な4方向タイマー・バースト撮影 |
| `src/services/speech.ts` | 音声初期化・時間制限・音声なしのフォールバック |
| `src/vision/detector.ts` | 生地領域推定・画素解析・連結成分・座標変換 |
| `src/vision/frames.ts` | 鮮明フレーム選択・時系列一致検査 |
| `src/components/AnnotatedImage.tsx` | 枠の描画と拡大 |
| `src/components/Developer.tsx` | 開発用画像検証画面 |
| `src/App.tsx` | 画面遷移・状態・キャンセル・結果管理 |

実機で調整する値（すべて `src/config.ts`）：

| 設定 | 初期値 | 調整の目安 |
| --- | --- | --- |
| brightnessThreshold | 170 | 白いシールが暗く撮れる場合に下げる。反射の誤検出に注意 |
| contrastThreshold | 90 | 生地と候補の明暗差。下げると薄い反射を拾いやすい |
| darkThreshold | 85 | 黒い生地の最大明度。照明・露出に合わせる |
| minArea / maxArea | 18 / 2600 | 幅480pxの解析画像上の面積。実際の3cmシールの画素面積で判断 |
| regionMargin | 0.025 | ガイドから内側へ狭める余白（画像全体に対する割合） |
| minSurroundingDark | 0.75 | 候補周囲の暗い生地の割合。下げると背景を拾う危険が増す |
| minDarkCoverage | 0.18 | ガイド内の最大暗領域の必要割合。側面の判定に影響 |
| minSharpness | 5 | 簡易ブレ評価。実画像で調整が必要 |
| preparationSeconds / directionSeconds / countdownSeconds | 3 / 6 / 3 | 撮影開始前・方向ごと・数字の表示時間（秒） |
| frameCount / burstMilliseconds | 4 / 750 | 最後のバースト枚数・撮影期間 |

時間設定は `directionSeconds >= countdownSeconds`、`countdownSeconds >= 1`、`0 <= burstMilliseconds <= 1000`、`frameCount >= 2` を守ってください。約27秒に解析時間が加わります。

## HTTPSで公開する

`netlify.toml` と `vercel.json` を同梱しています。CSP、カメラのみのPermissions-Policy、埋め込み禁止、Referrer-Policyを設定しています。アプリはモデル・外部API・外部フォントへの通信を必要としません。

### Netlify（Git連携）

1. このコードをGitHubのmainへコミット・プッシュします（この作業では実行していません）。
2. NetlifyでAdd new project → Import an existing projectを選び、CAMERAリポジトリを接続。
3. リポジトリ直下がルート。ビルド・公開先は `netlify.toml` から読まれます。
4. デプロイ完了後、Netlifyが発行する実際の `https://…netlify.app` をiPhone Safariで開く。

Git連携前でも、`npm run build` の出力 `dist` をNetlifyの手動デプロイにアップロードできます。ただし、ファイルのみの手動デプロイでは `netlify.toml` のヘッダーが適用されない場合があるため、推奨はGit連携です。

### Vercel

1. コードをGitHubへ保存し、VercelのAdd New Projectでインポート。
2. Framework Preset: Vite、Root: リポジトリ直下、Node.js: 24。
3. `vercel.json` のビルド・出力・ヘッダー設定を確認しDeploy。
4. Vercelが発行する実際のHTTPS URLでテスト。

ホスティングアカウントを使用した公開は未実施です。公開済みURLはありません。トークンをチャットやソースへ書かないでください。

## iPhone実機の受け入れテスト

1. 最新のiPhone SafariでHTTPS公開URLを開く（アプリ内ブラウザやiframeではなくSafariを使用）。
2. 均一な照明、白かグレーの壁、黒い無地のセーター、約3cm四方の白いシールを用意。
3. スマホを胸の高さに固定。約1.5〜2m離れ、顔〜腰を映す。プレビューの胴体枠に服を収め、服の両側に背景が見える位置に調整。
4. カメラを許可し、端末の音量・音声案内を確認。開始を押してから立ち位置へ移動。
5. 正面→右90度→背面→さらに右90度の順に、各数字が消えるまで静止。最後の0.75秒がフレーム取得時間。
6. 背面タブで白いシールの位置と検出枠を確認。位置を変更・除去して再撮影。
7. `docs/TESTING.md` の記録表に試行ごとの結果を記入。シールなしも同じ照明・距離で実施。
8. カメラ拒否、音声オフ、背景移行、中止、再撮影も実機で確認。

単眼の明暗検出であり、清潔さの保証や衣服全域の検査ではありません。判定不能方向は撮り直してください。

## プライバシー

画像・フレームはメモリのみで処理します。外部画像API、クラウド保存、ログイン、追跡、分析SDK、永続的履歴はありません。終了・再撮影で画像参照を破棄し、メモリ回収はブラウザに委ねます。撮影中の中止、解析への遷移、終了、バックグラウンド移行でカメラトラックを停止します。ページ初期表示ではカメラへアクセスしません。
