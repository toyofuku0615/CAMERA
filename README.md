# CAMERA

「伴走するスマートフォンから、人を送り出すスマートフォンへ」。iPhoneを固定し、一周して身だしなみを確認するReact / TypeScript / Viteアプリです。

起動するとフロントカメラと赤い撮影ボタンだけを表示します。撮影・解析が十分で、検出対象の候補がなかった場合だけ、黒い画面に「いってらっしゃい」を表示し、4.5秒後にカメラへ戻ります。

## 開発

Node.js 24 / npm 11。APIキー、アカウント、バックエンド、有料サービスは不要です。

```sh
cd /workspace/CAMERA
npm ci
npm run dev
npm run build
npm test
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

Playwrightの管理ブラウザを使う場合は `npx playwright install chromium` を実行してから `npm run test:e2e` を使ってください。Linuxではブラウザのシステム依存関係も必要です。標準のE2E設定は1ワーカーで、約3分かかります。

`npm ci` のpostinstall、dev/buildの事前処理が、バージョン・integrityを固定した公式MediaPipe npmパッケージから `public/vision/` にモデルとWASMをコピーします。このディレクトリは生成物で、Git管理しません。ビルドすると `dist/vision/` にも含まれます。実行時のCDNアクセスはありません。初回の解析時に同一オリジンからモデルを読み込むため、ホスティング先で生成物を配信する必要があります。

`npm run preview` で本番ビルドを確認できます。開発時だけ `/dev` に画素検出の調整画面があります。この画面は人物モデルを使わず、正常判定には使用しません。製品UIに設定やメニューはありません。

## 撮影と結果

- 起動時にカメラ許可を要求。許可がない場合は短い案内と再開操作だけを表示。
- 1タップで3秒の準備、各6秒の正面→右側面→背面→左側面。本人が左へ90度ずつ回ると右側面から確認できます。
- 各方向の最後の0.75秒で、ライブ映像から4枚の実フレームを取得。動画ファイルの保存・再生は行いません。
- 撮影中はプレビューを維持し、短い日本語音声と控えめな文字・数字で案内。停止ボタンは同じ位置の赤い四角へ変わります。
- 候補がある場合は、その候補が映る最も鮮明な実フレームだけを表示。細いリング、短い説明、左右スワイプ、タップ拡大・ピンチ・移動、再撮影に対応。
- 全方向で複数フレームの画角・向き・画質・画素解析が成立し、候補も未確定候補もない場合だけ「いってらっしゃい」。時間の経過だけでは正常扱いしません。
- 不足・中断・解析失敗は再撮影へ。確認済み候補と不足が混在する場合は静止画に不足の短い案内も表示。
- Safe Area、縦画面優先、横画面、キーボード、OSのモーション低減設定に対応。

## 検出方式と確認できる範囲

1. MediaPipe Pose Liteで33点の骨格と人物のセグメンテーションを推定。
2. 骨格から胴体・腕・脚の領域を作り、人物マスクの高信頼部分との交差を衣服領域の代替として使用。顔・手・足を除外。
3. MediaPipe Face Detectionと骨格を組み合わせて正面・側面を推定。背面は、正面で観測した肩と腰の左右関係が反転し、顔がなく、胴体が十分見える場合だけ候補として確認。曖昧な向きは判定不足。
4. 推定領域内の暗い連結成分、候補の形状・面積・局所的な明暗差・周囲の生地・鮮明度を検査。背景の明るさだけで判定しません。服の端や大きな明るい領域など、評価しきれない候補も正常扱いしません。
5. 同じ方向の連続フレームで位置の一致を確認し、重複を統合。候補ごとに最も鮮明なフレームと、その画像固有の座標を保持。

**検出対象は主に黒い無地の服上の明るいテープ・目立つ白い付着物の候補です。** 細長い明るい成分にも対応しましたが、微細な糸くずの実物精度は未測定です。色や柄のある服、黒いゴミ、しわ・着崩れ全般は信頼して判定できないため、検出機能があるとは主張しません。衣服の意味的な分類や衣服全表面の検査ではありません。

人物マスクと骨格は機械学習による推定です。全身・向きの物理的な保証ではなく、横向きの遮蔽、背面での左右の取り違え、複数人、低照度、反射などで確認不足になり得ます。最初の正面で顔が確認できなければ背面も確認済みにはしません。フレーム間の統合は方向ごとに行い、別方向に映った同じ物体の同一性は保証しません。

今回使用するMediaPipe JavaScript Solutionsは旧APIです。公式npm配布のモデルを同一オリジンに収められる方式を選びました。旧Face Detectionランタイムが動的JavaScript生成を使うため、公開CSPのscript-srcに `unsafe-eval` が必要です（実行確認済み）。スクリプト配信・外部接続は同一オリジンに限定していますが、動的実行のCSP制限は緩くなります。新しいTasks APIへの移行、各iPhoneでのメモリ・推論時間・向きの精度測定は今後の課題です。モデル、撮影画像、検出結果を生成・偽装するフォールバックはありません。

## 座標・プライバシー

プレビューはCSSでミラー表示し、取得した実画像はCanvasで一度だけ反転します。推定、画素解析、JPEG、SVGリングはすべて同じ反転済み座標です。表示は画像とSVGの両方をcontainし、縦横比や画面回転でリングだけがずれることを防ぎます。候補が異なるフレームに映る場合も、それぞれの画像と座標を対にして保持します。

撮影と推論は端末内で実行し、画像のアップロード、永続保存、追跡は行いません。停止・解析開始・バックグラウンド移行・ページ終了でカメラトラックを停止します。フレームのCanvasは処理後にサイズを0にし、結果の画像参照も再撮影や終了時に破棄します。モデルのGPU/WASM処理も解析後に閉じます。

## iPhone実機での確認

iPhone Safariのカメラ利用にはHTTPSが必要です。`netlify.toml` / `vercel.json` は同一オリジンのWASM、カメラ権限、SPA経路を設定しています。公開はこの変更では行っていません。

スマホを固定し、明るい場所で頭から足元まで画面に収めてください。最初は正面、案内に合わせて左へ回り、各方向の数字が消えるまで静止します。Safari実機で、カメラ許可、音声、方向の推定、背景の違い、シールの移動・除去、横画面、背景移行を確認する必要があります。
