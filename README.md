# CAMERA

「伴走するスマートフォンから、人を送り出すスマートフォンへ」。iPhoneを固定し、正面から背面へゆっくり向きを変えて身だしなみを確認するReact / TypeScript / Viteアプリです。

起動するとフロントカメラと赤い撮影ボタンだけを表示します。撮影・解析が十分で、検出対象の候補がなかった場合だけ、黒い画面に「いってらっしゃい」を表示し、4.5秒後にカメラへ戻ります。

## 開発

Node.js 24 / npm 11。APIキー、アカウント、バックエンド、有料サービスは不要です。

```sh
cd /workspace/CAMERA
npm ci
npm run dev
npm run build
npm test
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

Playwrightの管理ブラウザを使う場合は `npx playwright install chromium` を実行してから `npm run test:e2e` を使ってください。Linuxではブラウザのシステム依存関係も必要です。標準のE2E設定は1ワーカーです。実際に18秒の動画を複数回録画するため、全体で数分かかります。

`npm ci` のpostinstall、dev/buildの事前処理が、バージョン・integrityを固定した公式MediaPipe npmパッケージから `public/vision/` にモデルとWASMをコピーします。このディレクトリは生成物で、Git管理しません。ビルドすると `dist/vision/` にも含まれます。実行時のCDNアクセスはありません。初回の解析時に同一オリジンからモデルを読み込むため、ホスティング先で生成物を配信する必要があります。

`npm run preview` で本番ビルドを確認できます。開発時だけ `/dev` に画素検出の調整画面があります。この画面は人物モデルを使わず、正常判定には使用しません。製品UIに設定やメニューはありません。

## 撮影と結果

- 起動時にカメラ許可を要求。許可がない場合は短い案内と再開操作だけを表示。
- 1タップで3秒の準備、その後18秒の連続動画を録画。最初の6秒は正面、次の6秒でゆっくり背中を向け、最後の6秒は背面で静止します。側面ごとの撮影や側面確認の条件はありません。
- MediaRecorderで実際の動画Blobを作成。SafariではMP4、対応ブラウザではWebMを使用します。録画後に動画をデコードし、0.5秒間隔、約36枚の実フレームを解析します。ライブプレビューからのバースト画像方式は廃止しました。
- 動画は端末メモリ内だけに保持し、ユーザーへ全体再生画面は出しません。読み取り不能・途中終了・空データを正常扱いする画像取得の代替処理はありません。
- 撮影中はプレビューを維持し、短い日本語音声と控えめな文字・数字で案内。停止ボタンは同じ位置の赤い四角へ変わります。
- 候補がある場合は、その候補が映る最も鮮明な実フレームだけを表示。細いリング、短い説明、左右スワイプ、タップ拡大・ピンチ・移動、再撮影に対応。
- 正面・背面それぞれで3枚以上かつ1秒以上にわたる実フレームの画角・向き・画質・画素解析が成立し、候補も未確定候補もない場合だけ「いってらっしゃい」。時間の経過だけでは正常扱いしません。
- 不足・中断・解析失敗は再撮影へ。確認済み候補と不足が混在する場合は静止画に不足の短い案内も表示。
- Safe Area、縦画面優先、横画面、キーボード、OSのモーション低減設定に対応。

## 検出方式と確認できる範囲

1. MediaPipe Pose Liteで33点の骨格と人物のセグメンテーションを推定。
2. 骨格から胴体・腕・脚の領域を作り、人物マスクの高信頼部分との交差を衣服領域の代替として使用。顔・手・足を除外。白い付着物が背景と混同されてマスクから抜ける場合に備え、衣服の内側で閉じている小さな穴だけ補完し、背景へは領域を広げません。
3. MediaPipe Face Detectionと骨格を組み合わせて正面・背面を推定。回転途中の横向きは内部で区別しますが、独立した確認対象にはしません。背面は、正面で観測した肩と腰の左右関係が反転し、顔がなく、胴体が十分見える場合だけ候補として確認。曖昧な向きは判定不足。鼻先・つま先が隠れる背面では耳と踵も画角の根拠に使い、隠れた手首だけを理由に全身不足とはしません。
4. 推定領域内の暗い連結成分、候補の形状・面積・局所的な明暗差・周囲の生地・鮮明度を検査。衣服領域の明るさに合わせてしきい値を調整し、背景の明るさだけで判定しません。服の端や大きな明るい領域など、評価しきれない候補も正常扱いしません。
5. 衣服領域に対する相対位置・面積と時刻から候補を統合。異なる時刻の2フレーム以上で確認した候補を残します。動画の過半数に映る必要はありません。候補ごとに最も鮮明な実フレーム、その時刻と画像固有の座標を保持。回転中や全身確認が不足したフレームでも実際に検出した候補は表示し、確認不足は別に伝えます。単発候補は正常判定を止めます。

**検出対象は主に黒・濃いグレーの無地の服上の明るいテープ・目立つ白い付着物の候補です。** 細長い明るい成分にも対応しましたが、微細な糸くずの実物精度は未測定です。色や柄のある服、黒いゴミ、しわ・着崩れ全般は信頼して判定できないため、検出機能があるとは主張しません。衣服の意味的な分類や衣服全表面の検査ではありません。

人物マスクと骨格は機械学習による推定です。全身・向きの物理的な保証ではなく、横向きの遮蔽、背面での左右の取り違え、複数人、低照度、反射などで確認不足になり得ます。最初の正面で顔が確認できなければ背面も確認済みにはしません。相対位置が近い回転途中の候補も統合しますが、正面と背面は分けます。別表面に映った同じ物体の同一性は保証しません。表示は最大16候補で、それを超えた場合や統合しきれない候補がある場合も確認完了にはしません。

今回使用するMediaPipe JavaScript Solutionsは旧APIです。公式npm配布のモデルを同一オリジンに収められる方式を選びました。旧Face Detectionランタイムが動的JavaScript生成を使うため、公開CSPのscript-srcに `unsafe-eval` が必要です（実行確認済み）。スクリプト配信・外部接続は同一オリジンに限定していますが、動的実行のCSP制限は緩くなります。新しいTasks APIへの移行、各iPhoneでのメモリ・推論時間・向きの精度測定は今後の課題です。モデル、撮影画像、検出結果を生成・偽装するフォールバックはありません。

## 座標・プライバシー

プレビューはCSSでミラー表示し、取得した実画像はCanvasで一度だけ反転します。推定、画素解析、JPEG、SVGリングはすべて同じ反転済み座標です。表示は画像とSVGの両方をcontainし、縦横比や画面回転でリングだけがずれることを防ぎます。候補が異なるフレームに映る場合も、それぞれの画像と座標を対にして保持します。

撮影と推論は端末内で実行し、画像のアップロード、永続保存、追跡は行いません。停止・解析開始・バックグラウンド移行・ページ終了でカメラトラックを停止します。動画のオブジェクトURLとデコード用videoは解析後・中断時に解放し、動画Blobの参照も破棄します。生フレームは一度に1枚だけ保持し、Canvasは処理後にサイズを0にします。結果のJPEG参照も再撮影や終了時に破棄します。録画データは48MiB以内、解析は150秒以内を上限とします。モデルのGPU/WASM処理も解析後に閉じます。

## iPhone実機での確認

iPhone Safariのカメラ利用にはHTTPSが必要です。`netlify.toml` / `vercel.json` は同一オリジンのWASM、カメラ権限、SPA経路を設定しています。手動公開用の `CAMERA-web.zip` を配布ブランチに保存しています。解凍した `CAMERA-web` フォルダをNetlifyへアップロードすると開けます。アプリをHTTPSへ公開する操作はユーザーが行います。

スマホを固定し、明るい場所で頭から足元まで画面に収めてください。最初は正面で静止し、音声か画面の案内に合わせてゆっくり背中を向け、撮影が終わるまで静止します。横向きで停止する必要はありません。Safari実機で、カメラ許可、音声、方向の推定、背景の違い、シールの移動・除去、横画面、背景移行を確認する必要があります。
