# BACKSTAGE

iPhone Safari向け服装チェックWebアプリ。React / TypeScript / Vite。無地の服に付いた、生地と明るさ・色が違う物の候補を対象にしています。まず黒い服＋白いシールを優先しつつ、明るい服＋暗い物、色付きの付着物にも対応する検出方式です。撮影画像は端末内だけで解析します。

本改修では、**服を直接切り分けてから、周囲の無地の生地との差を解析**します。肩・腰のランドマーク検出と「黒い生地が十分にあること」を必須とする条件を廃止しました。撮影・5画面のUI・デザインは維持しています。

**実物シールとiPhone実機による改修後の精度は未測定です。背景条件ごとの9/10・8/10目標を達成したとは判断していません。** 公開参照写真のモデル推論と、実写真に白いパッチ・背景を合成した試験は、実機の受け入れ試験と区別しています。

## 起動・ビルド

Node.js 24 LTS / npm 11。APIキー、ログイン、バックエンド不要。

```sh
cd /workspace/CAMERA
npm ci
npm run dev
```

`predev` と `prebuild` が `npm run prepare:vision` を実行します。初回だけGoogle公式の固定バージョンモデルを取得し、チェックサムを検証します。ビルド環境から `storage.googleapis.com` へのHTTPS接続とcurlが必要です。以降は検証済みキャッシュを再利用します。MediaPipeのWASMはnpmからコピーし、モデルとともに**自サイトから配信**するため、アプリ実行時に撮影画像の外部送信や第三者CDNへのアクセスは発生しません。

```sh
npm run build
npm run preview
npm test
npx playwright install chromium
npm run test:e2e
```

このクラウドでは `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e` を使用します。ブラウザのインストール先を変える場合は、インストールと実行に同じ `PLAYWRIGHT_BROWSERS_PATH` を指定してください。

iPhoneのカメラにはHTTPSが必要です。ViteのlocalhostやLANのHTTPアドレスは公開URLではありません。

## 維持した撮影体験

ホーム → 撮影準備 → 自動撮影 → 解析中 → 結果の5画面。フロントカメラ（`playsInline` / `muted`）、約3秒の準備＋正面・側面①・背面・側面②各6秒で約27秒。右90度ずつ回り、数字が消えるまで静止します。各方向の最後0.75秒で4枚取得します。音声が再生できなくても視覚カウントダウンで進行します。

検出枠、方向切替、画像拡大、全体再チェック、未確認方向だけの再撮影を維持しています。カメラ拒否・切断・取得失敗・服認識不足・モデル失敗を異物なしとして扱いません。背景を登録・指定する操作はありません。明るい室内で、逆光と手による服の遮蔽を避けてください。

## 無地の服の解析

1. MediaPipe Image Segmenterを静止画像モードで実行。Selfie Multiclassの背景／髪／肌／顔／服／その他の6分類から、服と前景、肌のマスクを取得。Pose Landmarkerを使用せず、肩や腰が取れなくても解析を進める。
2. 撮影ガイド付近に重なる服の連結成分を選ぶ。背景・肌を除外し、服の境界の不確かな数画素は解析対象から外す。服の色で領域を決めない。
3. 服に囲まれた小さいマスク穴は補完する。シールが「その他」や「背景」に分類されても囲まれた部分は残し、肌や背景につながる穴は補完しない。
4. 生地の明度・色の中央値と、外れ値の影響を抑えた緩やかな照明勾配を推定。基準から明るい／暗い／色が違う部分を抽出する。
5. 8近傍の連結成分を作る際に、大きく色が変わる隣接画素を分離し、シールと近くのしわが同じ枠になるのを抑える。面積・形状・充填率、周囲の均一さ、局所的な明暗差・色差を評価する。
6. フレームは鮮明度で順位付けするが、無地の生地に模様が少ないことだけでブレと判定しない。服の黒さだけで照明不足とせず、画像全体の明るさも見る。
7. 服マスクの範囲でフレームの移動・拡大縮小を合わせ、IoUと中心距離を併用して一致を判定。1枚でしか確認できなかった候補も**低確信度で保持**。別フレームだけの候補は、その実際の画像で表示する。

通常撮影では4枚を鮮明度で順位付けし、上位2枚のみモデル推論を実行します（計8回）。常時動画推論は行いません。モデル推論はメインスレッドで同期実行されるため、iPhoneで短い応答停止が起こり得ます。新モデルは従来のPoseモデルより大きく、実機の時間・メモリは未測定です。

服のマスクがない、服の候補が複数に分かれる、小さすぎる、肌の遮蔽が多い、柄や光の変化が大きい場合は判定不能とし、再撮影を案内します。品質が不十分でも測定できた候補は残します。解析不能を「付着物なし」と表示しません。

プレビューはCSSで反転、撮影時にCanvasで一度反転し、モデル・解析・結果画像・SVG枠は同じ座標系を使います。

## モデル・依存の固定

- `@mediapipe/tasks-vision`: **0.10.32**（完全固定、package-lock.jsonあり）
- 公式モデル: **selfie_multiclass_256x256 / float32 / 1**
- SHA-256: `c6748b1253a99067ef71f7e26ca71096cd449baefa8f101900ea23016507e0e0`
- 配布元: `https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_multiclass_256x256/float32/1/selfie_multiclass_256x256.tflite`

モデル約15.6MiB、WASMは端末に合うSIMD／非SIMDを使用。配信には通常の圧縮・キャッシュが利用できます。モデルとWASMの生成先 `public/vision/` はGit対象外で、ビルド時に再現します。ブラウザでもモデルSHA-256を検証します。読み込みに失敗すれば撮影開始を無効化し、明示的な再試行を表示します。終了・バックグラウンド移行でモデルのグラフとカメラを解放します。

## 開発者の診断画面

開発サーバーの `/dev` にJPEG／PNGを最大8枚入力。通常の本番UIには存在しません。

- 元画像、人物マスク、実際の服の解析マスクと範囲
- 明暗差・色差の候補、採用候補、除外候補と理由（背景・服の範囲外・面積・明暗差など）
- フレームごとの結果、低確信度／複数確認、モデル推論時間
- 明暗差、色差、面積、充填率、服の境界の余白などの即時調整

閾値変更時はキャッシュしたマスクで再解析し、モデルは再実行しません。設定の変更は画面内だけで、採用値は `src/config.ts` へ反映します。

## 実機で調整する値

`src/config.ts` の `DETECTION`：`contrastThreshold`（明暗差45）、`colorDifferenceThreshold`（色差38）、`maxComponentColorStep`（連結候補内の隣接RGB差55）、`minFillRatio`（充填率0.45）、`minArea / maxArea`（解析幅480pxで18 / 2600画素）、`regionMargin`（服幅に対する境界除外0.025）、`minSurroundingFabric`（周辺に生地がある割合0.7）、`maxSurroundingVariation`（周囲の明度ばらつき28）、`minPlainCoverage`（均一生地0.7）、`minExposure`（画像全体の95パーセンタイル明度12）。モデルの `PERSON.clothesThreshold`（0.45）、`skinThreshold`（0.45）、`maskThreshold`（0.55）、`TEMPORAL.centerToleranceRatio`（服範囲の対角長の0.035）、`minimumOverlap`（0.2）、`maxAnalyzedFrames`（2）も調整可能です。

調整前にマスクと候補除外理由を確認してください。無差別に閾値を下げると反射・肌・アクセサリーを拾います。通常の撮影設定は従来どおり `CAPTURE` で管理します。

## HTTPS公開

Netlifyはリポジトリ接続後 `netlify.toml` を使用（Node24、`npm ci && npm run build`、公開先dist）。VercelはリポジトリをViteプロジェクトとして接続し `vercel.json` を使用。Root Directoryはリポジトリ直下。ビルド環境のGoogleモデル配布元への通信が必要です。CSPに `wasm-unsafe-eval` を追加し、画像は自サイト・data/blobのみ、通信は自サイトのみ、カメラ以外の権限は無効化しています。

公開後、発行された実際のHTTPS URLをiPhone Safariで開き、カメラ・日本語音声・4方向・背景移行・中止・シールの移動と除去を確認してください。本作業ではホスティングへのデプロイは行っていません。

## 制約

- 実物シール／実機iPhone／6種類の実際の背景での精度と処理時間は未検証。
- 視認できないシール、逆光、暗い服と背景が識別不能な入力、服の端、手の遮蔽、非常に小さいシールは見落とし得る。
- 見た目の差に基づく候補なので、ロゴ・アクセサリー・強い反射をシールと意味的に区別できない。
- Image Segmenterにも認識失敗はあり、人物数を確実に数えるモデルではない。1人で上半身を大きく写す。服だけの接写、背面・側面について実物の検証が必要。
- 模様の少なさはブレ評価に使用しない。ブレを確実に検出・排除する保証はない。静止フレームの選択と候補の面積・形状・差の評価による抑制のみ。
- 単発の高コントラスト反射も低確信度で残る場合がある。枠は必ず実際の画像で目視確認。
- 上位2フレーム以外はモデルで解析しない。必要に応じ診断画面で全画像を比較する。
- 同じ色で見分けにくい物、細い糸・薄いネックレス・毛玉など、微小／低充填率の物は対象外。見た目の差がある全ての異物を検出する保証はない。
- 無地の色違いの服は検出アルゴリズムの対象だが実機精度は未測定。柄のある服、強いしわ、複数色の服には対応しない。

ログイン、外部画像API、画像のクラウド保存、分析・追跡SDK、履歴はありません。撮影フレームと結果はメモリのみ。終了で参照とモデルグラフを破棄し、メモリ回収はブラウザに委ねます。
